## 9. T-103F allow-list 安全缺陷修复记录（独立验证 FAIL 后补，合同 contract-T-103F-v1）

### 9.1 缺陷与根因（独立验证实证 + 本修复复现）

- **H-1（High）`_tokenize` 裸 `$`/反引号死循环挂起**：`inspect/ansible_runner.py` `_tokenize` 的内层词扫描把 `$`/反引号列为停止字符，但外层分派不处理二者 → `i` 不前进 → 无限循环。复现：修复前 `parse_binaries('free -m; $(rm -rf /)')` 挂起（本修复以外部 15s 硬超时复现仍无返回，被终止）；`validate_command_specs` 同型触发。
- **H-2（High）双引号内命令替换/反引号整体当参数跳过 → 绕过 allow-list**：修复前 `parse_binaries('free -m "$(rm -rf /)"')` 返回 `['free']` 被 ACCEPT（引号整体为一个词、词内 `$()` 不被检查）；shell 在双引号内会展开命令替换 → G0 启用真实执行后即目标主机命令执行风险。`$VAR`、双引号内反引号同型。
- 报告失实：用例数实为 test_inventory 34 / test_ansible_runner 62 / 合计 96（报告称 36/98，且 36+62≠96 自相矛盾）；§6"注入类命令一律拒绝"在 H-2 修复前不成立。

### 9.2 修复内容（仅触及 _tokenize / parse_binaries / validate_command_specs 文档与校验逻辑）

1. `_tokenize`：`$`/反引号按普通词字符处理（不再作停止字符）→ 扫描每轮至少前进一个字符，裸 `$`/反引号不再死循环（H-1）；注入判定下沉至 parse_binaries。
2. `parse_binaries`：任一 token 含 `$` 或反引号（命令替换 `$()`/反引号、变量展开 `$VAR`，含双引号内整体成词）即抛 `CommandNotAllowedError`（H-1/H-2 一律拒绝）。allow-list 注册表模板经 profile 安全字符集校验（_SAFE_WORD/_SAFE_UNIT/_SAFE_PATH）后不可能含这两个字符 → 合法指标命令不受影响（对照验证通过）。
3. `validate_command_specs`：拒绝条件文档补"命令含命令替换/变量展开指示符（`$`/反引号，含引号内）"；校验链经 parse_binaries 抛错直达门禁（执行路径同样拒绝）。
