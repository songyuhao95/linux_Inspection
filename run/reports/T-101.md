## 5. 风险与未决（需主会话知悉）

1. **AC-2 本机编码问题（建议主会话处理）**：本机（Windows，locale cp936）`python` 的 subprocess `text=True` 默认 GBK 解码。AC-1 的 grep -F 按 UTF-8 字节匹配（实测通过），因此 CLI 输出必须保持 UTF-8；AC-2 逐字命令在本机必然解码失败。建议：AC 复跑统一加 `PYTHONUTF8=1` 前缀（本机实测 AC-2 即 PASS），或修订 AC-2 为 `encoding='utf-8'`。Linux/WSL 环境无此问题。实现侧已做跨平台正确输出（stdout/stderr 强制 UTF-8）。
2. **包名 `inspect` 与标准库同名（已解决，建议长期整改）**：仓库根在 sys.path[0] 时（`python -m pytest`/`python -m inspect.cli`）本包遮蔽标准库，pytest 启动即崩。解决：`inspect/__init__.py` 吸收标准库 inspect（加载真实 stdlib 模块 → `sys.modules['inspect']` 替换 → 本目录挂为其 `__path__`），效果：`import inspect` 得到标准库（pytest/logging/traceback 行为不变），`import inspect.cli/metrics` 与 `python -m inspect.cli` 正常。已实测：pytest 39 用例全绿、`python -m inspect.cli --list-metrics` rc=0、`inspect.getframeinfo` 可用、`inspect.metrics` 可导入。长期替代方案：包目录改名（如 `inspect_pkg`）并同步 inspect.sh 与 technical-design §3，需 G2 变更审批——本任务未自作主张改名。
3. **AC-3 expected_exit 语义**：合同记录 expected_exit=2，但 test_command 自身在被断言行为成立时退出 0（`test $? -eq 2` 判定通过即 0）。若 AC 运行器按命令自身退出码==expected_exit 判定，AC-3 在任何正确实现下都不可能成立，需按“断言语义”解释（AC-1 同理为 grep 退出 0）。
4. **默认巡检路径返回 10**：T-101 阶段 `inspect.sh`（无参/本机）明确报“管线模块未实现”退出 10（cli-contract §4 技术失败类），不伪造成功；编排主体由 T-103..T-108 交付模块后经 run_inspection() 惰性挂接（模块探测 find_spec，未就绪→10）。
5. 未实现中间件参数（如 `--profile kafka-unknown`）→ stderr“不支持”+ 退出码 2（cli-contract §1.4/§3），已实测。
